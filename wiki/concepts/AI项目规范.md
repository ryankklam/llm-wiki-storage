# AI项目规范

## 定义

**AI项目规范**是企业级 AI 编程项目中约束 AI 行为的一整套规则体系，核心载体是项目根目录下的 rules.md / CLAUDE.md 文件。它定义了 AI 能做什么、不能做什么、怎么做，是工业级 AI 项目管理的基石。

## 核心特征

### 工业级要求
- **可量化**：每条规则必须能量化、能验证
- **有红线**：明确禁止项，没有红线的规则等于没规则
- **有原因**：每条约束附"为什么"，AI 知道为什么才会真正遵循
- **控长度**：500 字以内最佳，防止 AI 漏项

### 与人工代码规范的区别
| 维度 | 人工代码规范 | AI项目规范 |
|------|-------------|-----------|
| 读者 | 人类开发者 | AI Agent |
| 语言 | 自然语言 + 示例 | 精确术语 + 边界定义 |
| 约束方式 | 建议性为主 | 强制性红线 |
| 更新频率 | 随版本迭代 | 随项目迭代实时维护 |

## 核心组成

### 1. 项目边界定义
- **是什么**：项目定位、需求场景
- **不是什么**：明确排除的范围（如"不是 CMS"、"不处理敏感数据"）

### 2. 技术栈约束
- 写具体版本号，不写名字（如 React 19、Tailwind CSS v4）
- 禁止引入不必要的框架

### 3. 代码规范
- 复用策略（同一 UI 模式不能出现两次）
- 目录规范
- 文件组织原则

### 4. 质量约束
- TypeScript 原则
- 组件规范
- API 接口规范

### 5. 禁止项（红线）
- 明确列出 AI 绝对不能做的事
- 禁止项优先于允许项

## 关键信息

- 真正拉开企业级工程师和普通人差距的，是能不能让 AI 按规则入手（来源：[[2026-06-12-企业AI项目rules红线]]）
- 管 AI 跟管项目，本来就是同一件事。把规则立在工程最前面，比后面任何补救都管用
- 这套规范不是拍脑袋定的，是一条条在真实项目里被坑过、改过才摸出来的
