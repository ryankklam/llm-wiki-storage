# 数据 Agent 四层架构

## 定义

**数据 Agent 四层架构是 Anthropic 提出的用于构建高准确率数据分析 Agent 的系统化方法**，通过四层递进的设计，将混乱数据转化为可信答案。

## 第一层：数据基础

### 目标
在 Agent 开始搜索之前，先把数据世界整理到足够清楚。

### 四个关键做法

1. **创建官方数据集（Canonical Data Sets）**
   - 先挑最核心、最常问、最容易错的概念
   - 非官方版本要么废弃、要么降级、要么标注编辑
   - 目标：Agent 收一个概念时，稳定碰到被治理过的答案

2. **标准要强势执行**
   - 工具层面：Agent 结构性地导向官方模型
   - 代码检查层面（CI）：绕过官方模型会被拦住
   - 组织层面：下游团队要基于治理层构建

3. **供给维护（Co-location）**
   - 数据建模代码、语义层定义、参考文档、看板定义、数据测试、Schema 文档放同一仓库
   - CI 做依赖检查：改了模型必须同步改文档

4. **元数据当成正式产品维护**
   - 表名、字段含义、指标定义、负责人、更新频率、表状态
   - 对 Agent 来说，元数据就是路标

## 第二层：可信来源（Source of Truth）

### 目标
确定信息的优先级和来源可信度。

### 信任层级
1. **语义层**（最高）：公司批准过的指标接口
2. **血缘图**：回答"数字从哪来"
3. **参考文档和业务上下文**：帮助理解用户意图
4. **历史 SQL**（最低）：可当原料，不能当真相来源

### 反直觉发现
- 让 LLM 自动从原始表生成指标定义是负收益
- 直接喂全量 SQL 语料准确率提升不到 1%
- 关键在于信息的结构化编排，而非信息量

## 第三层：Skills

### 知识 Skill
- 顶层路由器，先查语义层，再按需加载领域参考文档
- 搜索范围从整个数仓缩小到几十个精选文件

### 流程 Skill
- 规定资深分析师的工作顺序
- 打包可复用分析模式（留存曲线、比率分解、漏斗分析等）

### 参考文档结构
- 业务上下文
- 实体粒度（一行数据代表什么）
- 标准过滤条件（默认排除什么）
- 坑点（资深分析师知道但新人不知道的）
- 路由出发条件（遇到哪类问题看哪套资料）

### 维护要求
- Skills 与数据模型同仓库
- 约 90% 的模型 PR 包含 Skills 变更
- 不更新就会从导航变成旧地图

## 第四层：验证（Validation）

### 离线评测
- 三类评测题：基于看板的常见问题、罕见问题、用户纠正
- 追求接近 100% 准确率
- 结果落进数仓，能查趋势

### 消融实验
- 每次只改一个组件，用固定评测集对比
- 最有价值的发现：全量 SQL 语料无效果

### 上线后验证
- **对抗审查**：子 Agent 挑错，准确率 +6%，Token +32%，延迟 +72%
- **来源追溯**：标明答案来源、新鲜度、负责人
- **被动监控**：追踪语义层使用比例和纠错语言比例
- **主动纠错收集**：定时扫描业务频道，自动创建修复 PR

### 未解决
- **静默失败**：答案错了但看起来合理，没人指出来
