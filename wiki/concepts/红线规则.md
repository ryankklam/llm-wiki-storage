# 红线规则

## 定义

**红线规则**是 AI 项目规范中的绝对禁止项，是 AI 绝对不能触碰的边界。在 rules.md / CLAUDE.md 中，红线规则必须明确列出，且优先于允许项。没有红线的规则文件等于没有规则文件。

## 核心特征

### 红线规则的本质
- **绝对禁止**：不可商量、不可变通
- **优先表述**：先告诉 AI 别做什么，比告诉它做什么更管用
- **具体明确**：避免模糊描述，每条红线必须清晰可执行

### 常见红线示例

来源：[[2026-06-12-企业AI项目rules红线]]

- 不处理敏感数据
- 不引入不必要的框架
- 不直接写死 API Key（必须放环境变量）
- 同一 UI 模式不能出现两次（必须抽象成组件）
- 不修改已锁定的文件/配置

## 为什么红线规则至关重要

1. **AI 发散能力强**：大模型的发散能力很强，不给红线会写很多额外的东西
2. **聪明不等于听话**：模型越聪明，越需要明确边界
3. **预防成本远低于修复成本**：到 Code Review 才发现动了不该动的地方，代价巨大

## 关键信息

- "没有红线的 rules.md 等于没 rules.md。OpenAI、Claude、Cursor 都一样，没卡红线，代码越写越容易崩。"（来源：[[2026-06-12-企业AI项目rules红线]]）
- 禁止项优先是六个写法门道中最关键的一条
- 红线规则必须写在文档最前面，比写一百条要做什么都管用
