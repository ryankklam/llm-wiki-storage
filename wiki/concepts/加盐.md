# 加盐（Salt）

## 定义

加盐（Salt）是在密码哈希过程中，为每个用户生成一段随机字符串，将其与用户原始密码拼接后再进行哈希计算的技术。盐值与哈希结果一同存储，用于验证时复现相同的哈希过程。

## 为什么需要加盐

### 1. 废掉彩虹表（Rainbow Table）
彩虹表是攻击者预先计算好的"密码→哈希"对照表。加盐后，攻击者预先算好的表是针对纯密码的，每个用户都穿了不同的随机盐，那张表就对不上了。（来源：[[2026-07-03-面试问密码怎么存答MD5直接被淘汰]]）

### 2. 相同密码存出不同结果
就算两个用户设了同一个密码，因为盐不一样，存进库里的哈希也完全不同。攻击者没法一次撞库撞出一片人。（来源：[[2026-07-03-面试问密码怎么存答MD5直接被淘汰]]）

## 关键要求

| 要求 | 说明 |
|------|------|
| **每个用户盐必须不同** | 全站用一个盐或固定盐等于白加 |
| **盐要足够随机** | 使用密码学安全的随机数生成器 |
| **盐要足够长** | 一般至少16字节以上 |
| **盐无需保密** | 盐可以和哈希结果一起存储，其随机性本身提供安全性 |

## 加盐流程

```
注册时：
1. 生成随机盐："a3f8b2..."
2. 拼接：密码 + 盐 = "mypassworda3f8b2..."
3. 哈希：Hash("mypassworda3f8b2...") = "abc123..."
4. 存储：盐 + 哈希结果

登录时：
1. 取出用户存储的盐
2. 拼接：用户输入密码 + 盐
3. 哈希：用同样算法和参数计算
4. 比对：与存储的哈希值比较
```

## 常见错误

- **固定盐**：所有用户用同一个盐，彩虹表只需针对该盐重新计算一次
- **短盐**：太短的盐容易被穷举
- **伪随机盐**：使用普通随机数生成器而非密码学安全版本

## 现代便捷方案

BCrypt 等现代慢哈希算法已经把盐直接内置在最终结果中，开发者无需自己管理盐的存储。（来源：[[2026-07-03-面试问密码怎么存答MD5直接被淘汰]]）
