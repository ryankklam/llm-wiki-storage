# rules.md

## 定义

**rules.md 是立给 AI 的项目规则文件**，是 AI 编程项目中的"宪法"。AI 在执行任何操作前都必须先服从这一份规则。Claude Code 的 CLAUDE.md、Cursor 的 Cursor Rules，不管哪个工具，本质都是同一份东西。在 Spec-Kit 框架中，rules.md 是 Constitution（项目宪法）在 Cursor 等工具中的具体体现。

## 核心特征

### 技术定位
- **本质**：项目根目录下的 Markdown 规则文档
- **作用**：约束 AI 的行为边界，明确什么能动、什么绝对不能动
- **适用范围**：Claude Code、Cursor、Copilot 等所有 AI 编程工具

### 与 System Prompt 的关系
- rules.md / CLAUDE.md 是**项目级的 System Prompt**
- 比单次对话的 Prompt 更持久、更系统
- 是工业级 AI 项目管理的基石

## 五条硬规矩

来源：[[2026-06-12-企业AI项目rules红线]]

1. **先写清这个项目不是什么** — 不做哪类活，比写一百条要做什么都管用
2. **每条规则要能量化、能验证** — 还要附一个"为什么"，AI 知道为什么才会真正按规则走
3. **核心规则做和不做都列清楚** — 不留模糊地带
4. **技术栈不写名字，写具体版本号** — 不写版本号 AI 会自己挑最新的，依赖冲突一冒头回滚就是通宵
5. **整份文档压在五百字以内** — 超过这个字数 AI 漏掉关键项的概率明显上升

## 六个写法门道

来源：[[2026-06-12-企业AI项目rules红线]]

1. **禁止项优先** — 先告诉 AI 别做什么，比告诉它做什么更管用
2. **给理由不能只甩"不许这么写"** — 要把背后的原因写出来，AI 知道为什么比单纯被管着听话得多
3. **具体大于抽象** — "代码要优雅"这种模糊描述等于没写
4. **写代码复用策略** — AI 更喜欢新建代码而不是复用现有代码，必须明确约束
5. **专业术语要精准** — rules.md 不是写给人看的，是写给 AI 的语言书
6. **长度控制** — 500 字以内最佳，复杂项目不超过 2000 字

## 常见错误

### 写得模糊
"代码要优雅"、"性能要好"——好算好，AI 自己猜。后面反攻三轮都保不住。

### 只写要做什么，不写绝对不做什么是
没有红线的 rules.md 等于没 rules.md。OpenAI、Claude、Cursor 都一样，没卡红线代码越写越容易崩。

### 写得过长
不是写得越多越好。写太长 AI 反而漏掉关键那条。你以为写得越宽越保险，结果最该守的反而漏了。

## 关键信息

- rules.md 不是拍脑袋定的，是一条条在真实项目里被坑过、改过才摸出来的（来源：[[2026-06-12-企业AI项目rules红线]]）
- 管 AI 跟管项目，本来就是同一件事。把 rules.md 立在工程最前面，比后面任何补救都管用
- 思路想通后，工具换 Claude Code / Cursor / Copilot 都成立；模型换成下一代、下下一代也成立
