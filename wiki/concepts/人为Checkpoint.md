# 人为Checkpoint

> **领域**：Agent工程 / Skill设计

## 定义

**人为Checkpoint**（Human Checkpoint）是在[[Agent Loop]]或 Skill 执行流程中的关键节点上，主动插入人工判断环节的设计模式。其核心目的是在误差放大之前，利用人的综合经验判断进行纠偏。

## 核心原则

| 原则 | 说明 |
|------|------|
| **早期介入** | 越早期的判断点价值越高——在步骤3纠偏比步骤7纠偏节省更多Token和时间 |
| **高价值节点** | 只在需要综合经验判断的节点插入，机械重复部分仍由Agent自动完成 |
| **方向先于内容** | 先确认方向（如问卷调整方向），再让Agent生成具体内容 |
| **不可言说的判断** | 人的经验中存在"能感觉有问题但无法表述为规则"的部分，这是人相对于LLM的阶段性优势 |

## 典型流程

以问卷生成Skill为例（来自[[一启-AI]]的实践）：

1. Agent自动分析客户背景 → 2. Agent读取模板 → 3. Agent生成问卷调整方向 → **4. 🛑 人为Checkpoint：人审核方向** → 5. Agent根据确认后的方向生成完整问卷

## 为什么不能完全自动化

1. **模糊感知无法规则化**：人能感觉"这个问卷有问题"，但无法将这种感觉提炼成固定规则
2. **[[误差累积效应]]**：Agent每一步独立执行，早期误差会以乘数效应放大
3. **试错成本高**：10分钟的Skill运行如果结果不对，重跑又是10分钟
4. **收敛困难**：没有人工介入，Skill无法收敛到符合预期的结果

## 与其他概念的关系

- 实现了[[Skill半自动化]]的核心机制
- 对抗[[误差累积效应]]的关键手段
- 与[[Loop Engineering]]中的Run-Pause-Iterate循环一致
- 是[[Agent Loop]]中的人机协作模式
