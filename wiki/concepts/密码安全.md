# 密码安全

## 定义

密码安全（Password Security）是指用户在系统中使用的认证凭据（密码）从生成、传输、存储到验证的全生命周期安全保护措施。密码一旦泄露，可能导致用户在其他平台的账号也连带遭殃（密码复用问题），因此是后端开发的安全底线。

## 关键原则

### 1. 绝不明文存储
密码在数据库中不能以明文形式存储。任何有数据库访问权限的人（包括内部员工、DBA）都不应能看到用户原始密码。（来源：[[2026-07-03-面试问密码怎么存答MD5直接被淘汰]]）

### 2. 使用单向哈希而非加密
加密是可逆的（对称加密如AES、非对称加密如RSA），只要有密钥就能还原。密码存储需要的是**单向哈希（Hash）**——一种不可逆的指纹算法，只能验证不能还原。（来源：[[2026-07-03-面试问密码怎么存答MD5直接被淘汰]]）

### 3. 使用慢哈希算法
普通哈希算法（如MD5、SHA-1、SHA-256）设计目标是算得快，但"快"对密码存储是致命缺陷。攻击者每秒可计算几亿次，配合彩虹表和暴力破解可快速还原密码。必须使用专门的**慢哈希算法**（如BCrypt、SCrypt、Argon2）。（来源：[[2026-07-03-面试问密码怎么存答MD5直接被淘汰]]）

### 4. 每个密码独立加盐
给每个用户生成不同的随机盐（Salt），和密码拼接后再做哈希。这样即使两个用户密码相同，存储的哈希值也不同，且彩虹表直接失效。（来源：[[2026-07-03-面试问密码怎么存答MD5直接被淘汰]]）

## 标准存储流程

```
用户注册：
1. 生成随机盐（Salt）
2. 密码 + Salt → 慢哈希算法（如BCrypt）
3. 存储：哈希结果（内含Salt和成本参数）

用户登录：
1. 读取用户存储的哈希结果
2. 提取Salt和成本参数
3. 用户输入密码 + Salt + 同样参数 → 慢哈希
4. 比对两个哈希结果是否一致
```
