# Prompt工程规范

## 定义

**Prompt工程规范**是面向 AI 编程工具的 Prompt 编写最佳实践体系，核心原则包括"禁止项优先"、"量化可验证"、"控制长度"等。它是从通用 Prompt 工程向工业级 AI 项目规范演进的实践总结。

## 核心特征

### 从 Prompt 工程到项目规范
- **Prompt 工程 1.0**：单次对话指令，告诉模型怎么做
- **Prompt 工程 2.0（Context 工程）**：在正确时机给正确信息
- **Prompt 工程规范（工业级）**：持久化的项目规则文件（rules.md / CLAUDE.md）

### 核心原则

来源：[[2026-06-12-企业AI项目rules红线]]

1. **禁止项优先** — "我不允许你干什么" 比 "我允许你干什么" 效果更好
2. **具体大于抽象** — 避免"代码要优雅"这类模糊描述
3. **给理由** — 每条约束附"为什么"，AI 知道为什么比被管着听话得多
4. **控制长度** — 500 字以内最佳，过长反而让 AI 漏项
5. **写代码复用策略** — AI 天然倾向新建代码，必须明确约束复用
6. **专业术语精准** — 不是写给人看的，是写给 AI 的语言书

## 与 System Prompt 的关系

| 层级 | 载体 | 作用范围 | 持久性 |
|------|------|----------|--------|
| System Prompt | 对话级 | 单次会话 | 临时 |
| rules.md / CLAUDE.md | 项目级 | 整个项目 | 持久 |
| Constitution | 工具级（Specate） | 项目 + 工具链 | 持久 |

## 关键信息

- 聪明不等于听话。模型一代比一代聪明，但能不能让 AI 按规则干活才是差距所在（来源：[[2026-06-12-企业AI项目rules红线]]）
- 术语越精确、边界描述越清楚，AI 生成代码以及维护后续项目的过程中才会越来越规范
- 如果自己不太清楚专业术语，多和大模型沟通，让它把大白话转化成专业术语
