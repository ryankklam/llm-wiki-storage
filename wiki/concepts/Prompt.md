# Prompt

## 定义

**Prompt 是大模型的单次指令输入**，是大模型1.0时代 Prompt 工程的核心产物。它本身不创造任何新能力，只是把大模型已有的能力激发出来。

## 核心特征

### 技术定位
- **时代**：大模型1.0时代
- **工程**：Prompt工程
- **核心逻辑**：一次性告诉模型所有事

### 局限性
- **非标准化**：同一条 Prompt，换个大模型、换个上下文，输出效果可能天差地别
- **强依赖上下文**：无法脱离具体场景复用
- **不可自主调用**：只能由用户手动输入，无法被 Agent 工作流自主识别触发
- **无兜底能力**：容错率为0，无异常处理能力

## 与 Skill 的关系

> **Prompt 只是 Skill 众多组成模块中的一个可选环节**

Prompt 永远无法跳出大模型本身，去调取外部工具、读写文件、对接企业系统。而 Skill 是整合了 Context 工程、工具、流程的完整业务解决方案。

## 关键信息
- Prompt 的本质是引导大模型的输出方向（来源：[[2026-05-11-万物都可蒸馏Skill-5min讲清机制]]）
- 所有信息一次性全部喂给模型，让模型在单次推理中完成所有任务

## Anthropic 官方最佳实践

来源：[[2026-05-25-Anthropic内部Prompt写法]]

### 结构化 Prompt
- 使用 XML tags 分离角色、指南、政策、语气等
- 经验法则：如果你无法区分，模型也无法区分

### 创建输出契约
- 定义清晰的输出格式
- 使用 Stop Sequence 确保一致性

### 清理遗留补丁
- 删除针对旧模型的冗余指令
- 追踪防御性更改的原因

### 关键教训
- **指令不增加能力**：需要计算时给工具
- **说明权衡的两面**：不只说成本，也要说收益
- **模型可能扣留信息**：过度优化可能导致信息扣留

## Prompt 与 Skill 描述

来源：[[2026-06-17-AgentSkill过多4招提升命中]]

很多人优化错了方向：天天优化 Skill 内部 Prompt，却不优化 Skill 的描述信息。

- Skill 的 Name 和 Description 本质上就是向量检索里的标题和摘要
- Description 的清晰度直接决定路由命中率
- 优化 Skill 内部 Prompt 对路由没有帮助，因为模型可能根本选不到这个 Skill
- 正确的优化顺序：先优化 Description（让模型选对 Skill）→ 再优化内部 Prompt（让 Skill 执行得好）
