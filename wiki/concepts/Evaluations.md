# Evaluations

## 定义

**Evaluations（评估）是测试 Prompt 性能的系统化方法**，通过一组测试用例来验证 Prompt 的更改是否真正提升了性能。评估是 Prompt 工程中提供严谨性的关键环节。

## 核心作用

### 提供严谨性

- 了解对 Prompt 的更改是否真的与性能提升相关联
- 检测模型迁移或架构变更后的回归问题
- 为 Prompt 优化提供量化依据

### 区分问题类型

当系统不再正常工作时，评估帮助区分两种情况：
1. **行为问题**：新模型有能力但行为不同，可通过调整 Prompt 修复
2. **能力问题**：新模型能力不足，无法通过 Prompt 解决

## 评估套件设计

### 三种关键测试用例

| 类型 | 定义 | 作用 |
|------|------|------|
| 控制用例（Control Case） | 应该总是通过的用例 | 验证基本功能 |
| 边缘用例（Edge Cases） | 之前看到模型失败的用例 | 防止问题再次出现 |
| 能力边界用例 | 测试模型对自身能力的理解 | 确保正确升级或拒绝 |

### 示例：电信客服评估套件

1. **控制用例**：查询基础套餐的数据流量限额
2. **边缘用例**：
   - 计算按比例分摊的账单
   - 准确回答政策涵盖的问题
3. **能力边界用例**：
   - 账单错误时升级到人工
   - 不扣留有权限访问的信息

## 评估方法

### LLM 作为评判者

- 适用于需要主观判断的场景
- 可以评估回复质量、语气等

### 程序化检查

- 适用于有明确规则的场景
- 使用 Python 函数检查违规数量
- 更快速、更可靠

## 最佳实践

1. **代表性**：测试用例要代表实际使用场景
2. **可重复**：评估结果应该可重复验证
3. **迭代优化**：针对失败模式逐一解决
4. **版本控制**：记录每次评估的结果和更改

## 评估驱动开发流程

1. 建立评估套件
2. 运行初始评估，识别失败模式
3. 应用通用清理原则
4. 针对性解决每个失败模式
5. 重新评估验证改进
6. 重复直到所有用例通过
