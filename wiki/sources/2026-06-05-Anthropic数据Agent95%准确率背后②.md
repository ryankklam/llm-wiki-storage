## 视频内容摘要

本期视频深入拆解 Anthropic 数据 Agent 的四层架构，解释如何通过系统设计实现 95% 场景的自助业务分析和 90% 的准确率。

### 四层架构总览

Anthropic 把数据分析当成上下文和验证问题来处理，系统首先要对付三类失败：概念歧义、数据过期、检索失败。四层架构分别是：

1. **数据基础**：整理数据世界，创建官方数据集，强制执行标准，供给维护，元数据当成产品维护
2. **可信来源（Source of Truth）**：语义层优先，血缘图定位来源，业务上下文辅助理解
3. **Skills**：知识 Skill（路由器）+ 流程 Skill（工作顺序），把资深分析师经验编码进 Agent 路线
4. **验证（Validation）**：离线评测 + 消融实验 + 对抗审查 + 来源追溯 + 被动监控 + 主动纠错收集

### 第一层：数据基础

四个关键做法：
1. **创建官方数据集（Canonical Data Sets）**：先挑最核心、最常问、最容易错的概念收成标准答案
2. **标准要强势执行**：工具层面、代码检查层面（CI）、组织层面三管齐下
3. **供给维护（Co-location）**：数据建模代码、语义层定义、参考文档、看板定义、数据测试、Schema 文档放同一仓库
4. **元数据当成正式产品维护**：表名、字段、指标、负责人、更新频率、表状态等

### 第二层：可信来源

- **语义层（Semantic Layer）**：公司批准过的指标接口，机器可调用的官方指标目录
- **反直觉实验**：让 LLM 自动从原始表和查询日志生成指标定义，结果是负收益
- **血缘图和业务上下文**：回答"数字从哪来"，帮助 Agent 理解业务语境
- **历史 SQL 的局限**：直接喂全量 SQL 语料准确率提升不到 1%，关键在于结构化编排

### 第三层：Skills

- **知识 Skill**：顶层路由器，先查语义层，再按需加载领域参考文档
- **流程 Skill**：规定资深分析师的工作顺序，打包可复用分析模式
- **参考文档结构**：业务上下文、实体粒度、标准过滤条件、用法场景、坑点、路由出发条件
- **Skills 维护**：与数据模型同仓库，改模型必须同步改 Skills，约 90% 的模型 PR 包含 Skills 变更
- **准确率提升**：从 21%（无 Skills）到 95%+（有 Skills）

### 第四层：验证

- **离线评测**：基于看板的常见问题 + 罕见问题 + 用户纠正，追求接近 100% 准确率
- **消融实验**：最有价值的发现是负结果——全量 SQL 语料无效果，结构化编排才是关键
- **对抗审查**：子 Agent 挑错，准确率 +6%，代价 Token +32%、延迟 +72%
- **来源追溯（Provenance Footer）**：标明答案来源、数据新鲜度、负责人
- **被动监控**：追踪语义层使用比例和纠错语言比例
- **主动纠错收集**：定时扫描业务频道，自动创建修复 PR
- **未解决**：静默失败（Silent Failure）

### 核心结论

企业要做数据 Agent，不要一开始就对资料和权限。先画出答案路径：把每个关键概念的官方来源定下来，把去哪里找、怎么问、怎么验证的流程写清楚，再让 Agent 沿这条路径工作。

最小版本：少量官方数据集、基础语义层、离线评测、薄的 Knowledge Skill。
