# 为什么我现在更倾向于把Skill改成半自动？

> **来源**：小红书 @一启-AI

## 核心观点

一启-AI 分享了从"完全自动化"到"半自动化"的 Skill 设计理念转变。**核心结论：不要把人从 Skill 流程中抽出去，而要在关键节点插入[[人为Checkpoint]]。**

## 转录内容（LLM校正）

### 失败的起点：追求完全自动化

我们下面直接进入到 Skill 的高级技巧。

第一个技巧是我自己琢磨出来的。我一开始去构建 Skill 的核心目的只有一个：**我希望把这整个 SOP 完全自动化**。什么叫完全自动化呢？就是我完全不参与中间的任何过程，这个 Skill 给到 Agent 的时候，从 A 点到 B 点，我不用再打开它的文件去看它执行的过程。

大家是不是也有一样的想法？

然后后来有一天我想明白了——**这就是我失败的源头**。

### 关键转折：人不能从Loop中抽离

我发现如果你真的希望提升一个 Skill 的鲁棒性，就是它的稳定性，**一定要把人的 Checkpoint 加进去**。你不能把人从这个 Loop 里面抽出去。

听起来有点反常识——我们目的是为了自动化，我们目的就是我人不参与，你为什么一开始还要告诉我一定要人在里面？

我举个例子。我自己在打磨我的问卷生成的 Skill 的过程当中，经过了很多个版本的迭代。我始终发现这个 Skill 不能够产出符合我预期的结果——这个问卷设计的就是有问题。但是我自己讲不清楚它的问题在哪，我不知道怎么回事，**但是我能感觉它有问题，这个地方得改一下**。但是我没法把这种我模糊的感觉，提炼成一套非常固定且明确的规则。导致我那个 Skill 是没有办法收敛的。

### 流程太长，试错成本太高

然后有一天我想明白了。因为我发现我那个 Skill 的流程很长，对吧。一般大家的 Skill 执行过程都很长，可能需要花十几个步骤，然后中间可能有很多个点，它可能要跑十分钟。

我之前遇到的一个情况是：我让这个 Skill 跑，对吧，等了十分钟跑出来结果一塌糊涂。然后我就告诉他，你帮我重新再跑一下，哪个地方要改。改完了之后他又跑了十几分钟。尤其是 Cursor，点名批评一下，跑得太慢了。所以有的时候我会去用 Claude 或者 Cursor，我用他们再跑，他又跑了十分钟。

然后我就发现不对——**我不应该这么去设计我的 Skill**。

### 正确做法：在高价值判断点插入Checkpoint

我应该把人最宝贵的那种**综合经验判断**，主动地放到整个 Skill 执行过程当中，**具有高价值判断的点上面去**，要让两者交叉重合。

啥意思呢？我现在的 Skill 的执行流程大致是这样的：

1. 先去分析一下客户的背景信息
2. 提取一些关键的信息
3. 然后再去读一下我之前做好的这个问卷的模板（这个模板是一套同样的模板，需要去做一些特化）
4. 紧接着他会先去生成一份**针对这一家客户问卷调整的方向**（他不会真的去生成这个问卷，他会把这个方向先生成完了之后）
5. **这个 Skill 里面会有一个步骤告诉他停下来，去询问一下人的判断**——就是我这里说的[[人为Checkpoint]]

### 越早期的判断点价值越高

那为啥我把这个环节放到那么早期的阶段？大家可以思考一下。

**越早期的判断点价值越高**。为啥？因为如果你的判断点越往前，你能够保证你后面不会浪费你的 Token。你总共有十步，对吧，第三步如果就容易出问题，你等到第七步再去改，就说你改不过来了。但如果你在第三步就能把问题调整过来，后面的方向是能够相对稳定的。

### 与Loop Engineering的关系：误差乘数效应

这里面其实还涉及到一个点，就是跟我们前面说过的 Loop 的结构，就是那个循环——Run、Pause、Iterate。

你会发现每次的任务的执行，不是大家想象的那样——这个智能体非常牛，对吧，Claude 的很厉害，一开始就把任务想明白了，第一步干啥，第二步干啥，第三步干啥——**不是这样的**。

他都是先想完之后，先做第一步，做完之后决定第二步，第二步做完之后再做第三步。你会发现前面产生的误差，会随着你的每一步的单独的执行过程当中，这个误差会以[[误差累积效应|乘数效应]]叠加起来。所以当你第三步出现误差的时候，到第四步，这个误差会放大的。最后你会发现我的问卷完全不可用，因为我前面有误差，我没调整过来。

但我现在不一样——我在第三步就插入了人为Checkpoint，把误差在早期截断。
