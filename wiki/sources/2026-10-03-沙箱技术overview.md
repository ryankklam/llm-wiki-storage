## 一、沙箱是什么

**定义**：让不可信代码运行，但限制它所能造成的破坏。

> 目标不是阻止代码运行，而是限制**[[爆炸半径]]**。

### 威胁模型

- 云厂商：防别的租户
- 浏览器：防恶意网页
- Serverless：防函数逃逸
- AI Agent：防模型自己生成的代码（可能被提示词注入操控）

### 三个核心概念

| 概念 | 含义 |
|------|------|
| **隔离** | 让 A 看不到 B |
| **资源限制** | 让 A 用不光资源 |
| **权限控制** | 让 A 做不了某些操作 |

> ⚠️ 高频误区：Cgroups 只做资源限制，它**不是隔离边界**。

### 最重要的一句话

容器的隔离由内核提供，所以容器和宿主机之间**只有一个系统调用的距离**。

- 容器本质上就是宿主机上的一组普通进程
- Namespaces 改了它的视野
- Cgroups 限了它的资源
- 但它和宿主跑在同一个内核上
- 于是内核里任何一个提权漏洞都等于**容器逃逸**

**经典案例**：Dirty COW（写时复制漏洞），普通进程就能提权到 root，容器边界形同虚设。

## 二、沙箱技术光谱

整个沙箱技术就是在压取舍曲线：**隔离强度往上，性能密度就得往下**。谁能用更低的代价换到更强的隔离，谁就赢。

### 光谱低端：容器

容器不是单一技术，而是一组内核机制的组合：

| 机制 | 作用 |
|------|------|
| **Namespaces** | 管"看得见什么" |
| **Cgroups** | 管"能用多少" |
| **Capabilities** | 把 root 权限切碎 |
| **Seccomp** | 收窄系统调用 |
| **LSM**（AppArmor/SELinux） | 强制访问控制 |

**Seccomp** 是最关键的一层，用 BPF 程序过滤系统调用。

> 🎯 面试要点：必须用**白名单**，不要用黑名单。
> - 黑名单要不断追新系统调用
> - 存在绕过风险（如 x32 ABI 标志位，黑名单没处理就能直接绕过）

但要清楚：再多的 Seccomp 和 LSM 都改变不了一个事实——**系统调用最终还是由那个单体内核执行**。这就是容器的天花板。

### 光谱中端：gVisor

gVisor 换了个思路：在应用和宿主内核之间插一个**假内核**。

- 用 Go 语言在用户态重新实现了一个 Linux 内核，叫 **Sentry**
- Sentry 拦截并处理应用的所有系统调用
- 文件访问拆给另一个组件 **Gofer**，进一步缩小信任面
- 攻击面从整张系统调用表缩小到 Sentry 自己用到的那几个

**代价**：
1. **结构性成本**：Sentry 带来额外内存和多层穿透，优化不掉
2. **实现成本**：网络栈效率还在持续改进
3. **兼容性硬伤**：部分系统调用没有实现

> 一句话：gVisor 是用软件造一个假内核。

### 光谱高端：MicroVM

用硬件虚拟化造一道硬件强制的边界，但把虚拟机做得极轻。

**代表**：AWS Firecracker（同时服务 Lambda 和 Fargate）

三个关键数字：
- 启动时间 < **125ms**
- 每台虚拟机内存开销 < **5MB**
- 单机每秒最多创建 **150 台**

为什么又安全又轻？
- 极致裁剪：砍掉 Serverless 用不上的 BIOS、PCI、USB、GPU
- 设备越少，攻击面越小
- 不做完整的硬件初始化，启动自然快

> 这就是压 trade-off 曲线的典范。

### 光谱对比表

| 技术 | 内核 | 逃逸难度 | 特点 |
|------|------|----------|------|
| 容器 | 共享宿主内核 | 中等 | 兼容性+高密度 |
| gVisor | 用户态假内核（Sentry） | 需破 Sentry+宿主两层 | 极致轻量+强隔离，兼容性差 |
| MicroVM | 独立 guest 内核 | 需突破 Hypervisor | 兼容性+强隔离 |
| 独立主机 | 物理隔离 | 最高 | 最安全但最重 |

### 选型逻辑

- 要**兼容性 + 高密度** → 选容器（接受内核漏洞风险）
- 要**兼容性 + 强隔离** → 选 MicroVM
- 要**极致轻量 + 强隔离** → 选 gVisor（接受兼容性代价）

## 三、AI Agent 的沙箱

Agent 执行的是模型运行时才生成的代码，无法预先审计。传统的代码审计 + 签名的供应链思路全部失效。

### 三个新约束

1. **有状态任务**：要能暂停、恢复，文件系统要持久化
2. **凭证隔离**：凭证必须物理上不可达
   - 不能赌模型拿受限 token 做不到坏事
   - 因为模型能力一直在涨，这个假设总会过期
3. **网络出口控制**：既要能装依赖，又要防外泄，天然矛盾

### Anthropic 真实事故

出口白名单放行了自家 API 域名，攻击者用自己的 key 把工作区文件传到了自己的账户。

> 沙箱完美工作，数据照样外泄。

**教训**：分析不是"目标过滤器"，而是"能力授予"。
要问的不是"这个域名可不可信"，而是"这个域名上暴露了哪些功能"。

## 四、技术演进主线

```
共享内核有风险
  → 用 Seccomp 收窄系统调用
    → 但单体内核仍是执行者
      → gVisor 在用户态造内核（兼容性有代价）
        → MicroVM 给每个负载一个真内核
          → 传统虚拟机太重
            → Firecracker 裁到 125ms / 5MB
```

> 沙箱技术的演进就是在**隔离强度、性能密度、兼容性**这个三角里不断寻找新的平衡点。
