## 视频内容摘要

本视频深入讲解 AI Agent 四种范式的本质差异、适用场景和技术选型策略，帮助面试者从工程维度理解而非简单列举。

### 面试考察意图
1. **Agent 架构的工程判断力**：能否从延迟、可靠性、可观测性等维度评价一个范式
2. **技术选型判断力**：面向具体场景能否准确选出该用哪种范式

### 常见误区
四种范式不是线性进化关系，而是**不同维度的比较对象**：
- Tool Use：基础能力层
- ReAct：推理框架层
- Plan-and-Execute：控制流程层
- Multi-Agent：组织架构层

四层可以叠加而非互斥，例如 AutoGen 里的一个 Agent 可以同时用 ReAct、Function Calling，整体又是 Multi-Agent 架构。

### 四种范式详解

#### Tool Use（基础能力层）
- **定义**：模型根据上下文自主决定要不要调工具、调哪个、传什么参数
- **优势**：延迟低、架构简单
- **劣势**：多步推理时每步独立决策，缺少全局规划容易偏离目标
- **适用场景**：单一或简单调用，如查天气、发邮件

#### ReAct（推理框架层）
- **定义**：推理和行动交织进行，Thought-Action-Observation 三段循环
- **优势**：可解释性强，日志能看到每一步决策路径
- **代价**：延迟高，每多轮循环就多一次 LLM 调用
- **适用场景**：中等复杂度且对可观测性要求高的任务，如客服工单、数据分析

#### Plan-and-Execute（控制流程层）
- **定义**：先规划再执行，模型在动手前生成完整计划
- **优势**：解决 ReAct 缺乏全局视野的弱点
- **代价**：规划消耗推理资源，计划可能不准确
- **最佳实践**：在执行中引入重新规划机制
- **适用场景**：步骤多但结构清晰的任务，如大型代码重构、复杂数据处理流水线

#### Multi-Agent（组织架构层）
- **定义**：把复杂任务拆给多个专门 Agent，每个有自己的角色、工具和知识范围
- **优势**：职责分离，每个 Agent 的 Context Window 只需关注自己的范围
- **主流框架**：AutoGen、CrewAI
- **适用场景**：角色边界清晰的协作场景，如软件工程的多角色配合、内容编审发布流程

### 技术选型框架

**第一看任务复杂度：**
- 单步或少量调用 → Tool Use
- 多步推理 + 可解释性 → ReAct
- 步骤多且结构化高 → Plan-and-Execute
- 角色天然分离或单 Agent 上下文装不下 → Multi-Agent

**第二看延迟敏感度：**
- 实时交互 → Tool Use 或最简 ReAct
- 后台批处理 → Plan-and-Execute 或 Multi-Agent

**第三看可观测性需求：**
- ReAct 的循环是天然审计追踪
- Multi-Agent 需同时追踪多 Agent 状态，排查难度最高

### 核心原则
技术选型的核心不是找最好的范式，而是**用最少的复杂度解决当前问题**。范式越高级，系统复杂度越高，复杂度本身就是成本。
